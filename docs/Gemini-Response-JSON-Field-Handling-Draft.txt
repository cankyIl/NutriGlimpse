Applies to the default Gemini single-product scan. The same food fields are used for the original product and every alternative.
<food> below means product or an item in alternatives[].

MAIN RULES
- A missing, null, invalid or unverified source_url must not block the answer.
- Keep usable information; a missing optional field affects that field or product only.
- Missing nutrients are unknown, never zero.
- Display a retailer name as a suggestion. Do not request/display stock status.
- Show the aisle number and/or section returned by Gemini with its named store. A missing source URL or missing branch evidence must not hide the aisle. Missing aisle values remain absent. This is a store suggestion, not a stock guarantee or independently verified location.
- Existing nutrient consistency, dietary restriction and clinical boundaries remain.
- An unreadable/non-JSON provider response is different from an omitted JSON field: it still needs a clear error rather than fabricated results.

RESPONSE STRUCTURE

| JSON entry | Purpose | If absent or unavailable |
| --- | --- | --- |
| product | Original scanned product object | Show that the product could not be identified; keep the user's photo and offer another scan. Do not invent a product or rating. |
| alternatives | Array of recommended products | Keep the original result. Show only alternatives actually returned and eligible; up to three. Do not invent products to fill slots. use the alternatives through another LLM. Give the same prompt to gemini GPT 6 Luna in parallel to Gemini. It should happen simulataneously|
| <food>.title | Brand/product name in a concise title | Original: no identifiable product card. Alternative: skip only that unnamed alternative; keep other valid products. |
| <food>.rating | healthy, neutral or not_healthy | Keep available original food facts without a colored rating. An unrated alternative is not presented as a healthier recommendation. No rating is guessed. |
| <food>.reasons | Short explanation of rating or recommendation | Omit the explanation. Retain the rating when otherwise supported by the returned nutrients and existing checks. Do not invent reasons. |
| <food>.uncertainties | Model-reported limitations | Omit this list. Normal AI-estimate and missing-data notices still apply when appropriate. |
| <food>.nutrition | Object containing nutrient values | Keep the identified original and store information. Show nutrients as unknown; do not apply a health rating or recommend a product as healthier when every nutrient is unknown. But if the known nutrient is amount is unhealthy it is ok to use that information to characterize the product. its possible that its known that sodium is very high, but you dont know dietary fiber. Still it can be unhealthy because of high sodium |
| <food>.source_url | Nutrition-source link | Retain product, returned nutrients, model rating/reasons and otherwise eligible alternatives as unverified AI estimates. Omit the source link. Never reject the answer solely because this link is missing, invalid or unverified. |
| <food>.retailer_url | Optional retailer product-page link | Keep the suggested store name. Omit the store-source button when there is no usable link. Do not perform another search solely because this link is missing. |
| <food>.image_url | Product thumbnail link | Original: use the user's scan photo. Alternative: use the product placeholder. Keep the product information. Existing image-link checks still apply. |
| <food>.store | Suggested retailer name | If a current store exists, make at most one focused Gemini lookup for all alternatives missing a usable retailer name. If still absent, show Store: Not identified. Keep food facts and alternatives. |
| <food>.aisle | Optional aisle/section object | Omit the aisle line. Keep the store name and product card. |
| <food>.aisle.number | Aisle number/code | Show the returned section name alone if supplied; otherwise omit the aisle line. |
| <food>.aisle.section | Aisle name or store section | Show the returned aisle number alone if supplied; otherwise omit the aisle line. |
| <food>.aisle.store | Retailer associated with aisle evidence | Use the retailer returned with the aisle, falling back to the product store when omitted. A different suggested retailer does not erase the aisle. Do not label it as confirmed stock. |
| <food>.aisle.town | Town associated with aisle evidence | Keep any returned town; if omitted, leave town unknown and retain the aisle. |
| <food>.aisle.state | State associated with aisle evidence | Keep any returned state; if omitted, leave state unknown and retain the aisle. |
| <food>.aisle.source_url | Source supporting the current-store aisle | Omit the source link when unusable or unconfirmed; retain the returned aisle, store name and product answer. Do not fabricate a citation or mark branch evidence verified. |

Implementation notes:
- The JSON schema requests consistent keys; unknown values can be null. The backend also tolerates omitted optional fields.
- Package size and serving size are not required by this current prompt/response contract.
- Without quantity information, exact equal-portion nutrient comparisons are not established.
- Store suggestions are independent of confirmed inventory. No stock field is requested.
- The server records consented returned JSON and processing decisions for diagnosis; editing this draft does not itself deploy code or change the active model prompt.
